# AENIX ERP — Frontend Screen Inventory (screen families)

Version 0.1 | 2026-11-23 | FE-P0-001 | PROPOSED — planning only, **no screen is approved for build**

This document lists screen _families_ taken from the confirmed domain rules. It is not a UI design. Layouts, navigation, fields and visuals come from the owner's UI reference. Permission codes marked **(doc)** are examples quoted in `SECURITY-AND-AUDIT.md`/ADR-004. All others are **TBD in SEC-001**; the frontend must not invent them.

Personas: **S** = internal staff, **C** = customer portal, **V** = vendor portal.
Every screen must have loading, empty, error and permission-denied states, server-side paging/filter/sort for lists, and keyboard/screen-reader support.

## Fixed domain constraints the UI must respect

- Work Order **is** the Job. There is no separate "create Job" flow. Enquiry, Quotation and Contract are optional steps before it.
- Transport Jobs may have no warehouse activity. Warehouse stock and storage billing may run without a Job.
- Portal users only approve and view their own basic financial records. They never edit internal operations, and the UI never sends a party ID.
- Posted financial and stock documents are read-only. Corrections appear only as the reverse or adjust actions the API exposes.
