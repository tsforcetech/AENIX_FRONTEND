Version 0.1 | 2026-11-23 | FE-P0-001 | Owner of requests: Claude · Contract owner: Antigravity · Reviewer: DOBIS

**Update 2026-11-23:** AENIX `main` (`df295e0`, P0-001 backend bootstrap) now publishes `contracts/openapi/openapi-v1.json` with **technical endpoints only** (`/health/live`, `/health/ready`, `/api/v1/meta/version`). It confirms `X-Correlation-Id` on every response and RFC 7807 ProblemDetails with `correlationId`/`traceId` extensions. A reference copy is in this repository's `contracts/openapi/`; the source of truth stays in [AENIX](https://github.com/tsforcetech/AENIX/tree/main/contracts/openapi). Every business item below is **REQUESTED / PENDING** until Antigravity publishes it in a versioned OpenAPI document. The frontend implements no path, DTO or field from this list until then. Suggested shapes are _questions_, not specifications.

## Prototype view-models (FE-PROTO-001)

The clickable prototype uses **provisional** view-models in `src/domain/types.ts`, plus one `api.ts` adapter per module (see `docs/PROTOTYPE.md`). They show which fields the screens need, so Antigravity can use them as a **reference input** when designing contracts. They are **not** contracts and must not be treated as approved field names.

## Frontend commitments once contracts exist

- Generate types from the contract (`openapi-typescript`) into `src/api/generated/`, never hand-edit them, and run a CI drift check.
- Add contract tests that check the client's request and response handling against the contract examples.
- Send no party/tenant ID from portal screens, store no tokens in web storage, and retry only safe GETs.
